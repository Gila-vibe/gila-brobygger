# PROJECT.md – documentation scope

The canonical project context is the root [`PROJECT.md`](../PROJECT.md). This file exists because
earlier versions kept a second project document inside `docs/`; it now only points to the source
of truth so the two cannot drift apart.

Read, in this order:

1. [`../PROJECT.md`](../PROJECT.md) – organisation, goals, scope, audiences, constraints.
2. [`ORGANISATION.md`](ORGANISATION.md) – services, activities, experience and unknowns.
3. [`WEBSITE_SPEC.md`](WEBSITE_SPEC.md) – page inventory and requirements.
4. [`OWNER_REVIEW.md`](OWNER_REVIEW.md) – what is still unconfirmed.
5. [`APPROVAL_LOG.md`](APPROVAL_LOG.md) – approval and legal/DPO status.

Do not add project facts here. Add them to the root `PROJECT.md` or `docs/ORGANISATION.md`, so
there is exactly one place to maintain each fact.
